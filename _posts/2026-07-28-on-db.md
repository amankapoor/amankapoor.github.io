Pooling  
DBs create an OS process ~10mb each, and based on resource they are running a ceiling is there like 50-60 processes. But is infra is such that instances can be scaled, then these 50-50 can be 250-300 if multiple instances are created. Without a pooler, it will just expand leading to resources unavailable and thus new connections not able to connect. Pooler sits in between and multiplexes (multiple inputs -> single/limited output). So all clients share a few DB OS processes.  
100 client connections -> 100 OS processes (overload)  
100 client connections -> pooler (resources freed after transaction and provided to next connection in queue) -> 10 DB processes (normal)
